## Behavior and compatibility

`createTerminalGrid` composes four persistent terminal slots with one, two or four visible cells. Every cell retains its own market, interval, studies, drawings, pane preferences and alert document. Hiding a cell saves its workspace and releases its chart/feed while its armed alerts continue through the shared monitor. Reopening preserves alert occurrences, including once alerts triggered while parked.

Native controls select the visible layout, active cell and independent viewport/crosshair synchronization preferences. Host width determines one or two responsive columns; narrow grids keep a 360-pixel cell height floor and scroll internally. Explicit Save/Restore in the independent React example uses a separate grid storage key. Underlying terminal controls retain focused drafts during streaming in the source browser regressions; the final installed capture verifies saved storage bytes, not focused-draft replay.

Ready charts synchronize by loaded timestamps. Interaction/API navigation can lead neighbors; hydration, backfill and data-driven follow-latest movement remain local. Active selection alone does not jump viewports. Exact/nearest crosshairs resolve each target's own timestamps and values. Standalone analysis synchronization accepts an optional copied cause filter; omission preserves its previous behavior.

Grid workspace version1 nests four terminal workspaces, canonical terminal version5 and drawing version2, with strict historical migration through the existing decoders. Complete replacement validates and prepares before adoption. A valid adopted configuration can still encounter a later provider error. Supplied stores and monitors are independently borrowed; restore may replace borrowed stores with grid-owned stores while leaving the originals alive. External leases and monitor capacity participate in admission. See the [integration, persistence and ownership contract](../TERMINAL-CONTRACT.md#saved-terminal-grids).

Three constructions, three restores, tail batches, interactions, native wheel, exact/nearest synchronization and a minimum 120-second mixed session have fixed budgets.

Construction uses public monitor/grid creation, immediate workspace restore and actual paged history loading. The 4,000 ms bound includes elapsed hydration work and waits; raw synchronous dispatch and restore fulfillment remain separate. Tail and interaction work counts each actual render callback once. Actual cadence and misses must accompany timing percentiles.
