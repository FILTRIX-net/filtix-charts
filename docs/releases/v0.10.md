## Behavior and compatibility

`@filtix/alerts` adds persistent price-crossing rules, a headless store and a shared monitor. Armed rules keep monitoring their saved markets when the terminal displays another chart. Rules support upward, downward or either-direction crossings, once/repeat behavior, pause/rearm, labels and persisted trigger counts. The native Alerts editor preserves focused drafts during streaming.

A monitor shares one bounded latest-price feed per exact provider/symbol/interval and enforces 100 rules per store, 400 attached rules and 32 armed queries. Steady samples with unchanged transport status/error do not refresh monitor subscribers. Crossing events, reconnect/error changes and membership changes remain observable. Supplied stores and monitors are independently borrowed; teardown releases only owned resources.

Terminal workspace v5 includes alerts and preserves drawing documents v2. Exact historical v1–v4 saves migrate through owning codecs, adding empty alerts under the current scope. Historical nested-v1 and nested-v2 v4 types remain distinct. Older packages cannot read v5 saves. Host applications own persistence. See [integration and crossing semantics](../ALERTS.md).

Alerts run while the application is running and receiving data. History/reconnect establish a baseline without replaying missed crossings. There is no server-side monitoring or external notification delivery in this release.

The endpoint rule documents are identical, but transient recent-event UI differs: the initial terminal has 20 recent rows and the final remount has none. This does not establish sustained 100 batches/s across the run, physical display latency or live-market/device performance.
